Major project · simulation study

Quantum-safe communication between vehicles

Connected vehicles authenticate each other with elliptic-curve cryptography, which a large quantum computer will break. We tested both proposed replacements, quantum key distribution and post-quantum cryptography. We showed that three recently published authentication schemes for drones and autonomous vehicles [1–3] fail against seven concrete attacks. We then designed and formally verified a post-quantum vehicle handshake and measured what it costs on a crowded road.

The problem

V2V security today will not survive a quantum computer

Vehicles broadcast signed safety messages about ten times a second (position, speed, braking) and set up keys with each other for private exchanges. Today both rest on elliptic-curve cryptography (ECDSA and ECDH, as in IEEE 1609.2). Shor's algorithm solves the elliptic-curve discrete-log problem on a large quantum computer, so every signature could be forged and every recorded key exchange decrypted.

Two replacements are proposed. Quantum key distribution (QKD) uses physics: measuring a photon disturbs it, so an eavesdropper shows up as errors. Post-quantum cryptography (PQC) uses new mathematics that quantum computers are not known to break: NIST standardised ML-KEM and ML-DSA in 2024. Three recent schemes for drone and autonomous-vehicle authentication, PSRS-D2D [1], PSLAP [2] and P²AS-IoAV [3], each come with a formal security argument (a Real-or-Random proof and Scyther verification). The third already uses a post-quantum KEM. This project asks which approach actually works for vehicles, and at what cost.

Part 1 · Quantum key distribution

QKD works as theory says, but distance limits it

In BB84, Alice sends single photons in random bases; Bob measures in random bases; they keep the bits where the bases matched and compare a sample. An intercept-resend eavesdropper must guess bases too, and her wrong guesses show up as errors (QBER).

Errors in the kept bits are what give Eve away.

An eavesdropper cannot hide

200,000 photons per point. Dots are simulated, lines are the exact formula Q = e + f/4 − f·e/2 (e = channel noise, f = fraction intercepted). Largest deviation from theory: – standard errors over – settings.

Above the 11% line Alice and Bob abort. A clean channel detects Eve once she touches about 44% of the photons, and full interception produces a 25% error rate. Channel noise uses up part of that margin.

From raw bits to a secret key

Full pipeline: sifting, error estimation, Cascade error correction, verification and Toeplitz privacy amplification. 100,000 photons, 10 runs per point.

Measured key rates follow the prediction. Real error correction reveals about –× the theoretical minimum, so the key runs out near 10% error rather than the 11% of the Shor–Preskill bound. Across – runs, Alice and Bob never ended up with different keys (– mismatches).

Distance is the real limit

Fibre-like loss of 0.2 dB/km, 20% efficient detectors, an ideal single-photon source (an optimistic setting). 5 runs per distance.

The key rate falls – dB per km, exactly the channel loss, until detector noise overwhelms the signal: no key at – km. QKD also needs line-of-sight optics between moving cars and an authenticated classical channel, which itself needs PQC signatures.

Part 2 · Cryptanalysis

Three published schemes, seven successful attacks

The schemes are PSRS-D2D [1] (drone-to-drone, IEEE TMC 2026), PSLAP [2] (autonomous vehicle–drone, Computer Networks 2025) and P²AS-IoAV [3] (vehicle–UAV and UAV–cloud with CRYSTALS-Kyber, IEEE TVT 2026). Each was implemented from the paper's own equations and figures on real P-256 and ML-KEM cryptography. Every attacker gets only what the paper's threat model allows; the victim's true secret is used only to check the result. All – attacks on the three schemes recover it exactly. Scope of each attack (read before quoting a result)
  • PSLAP [2], session linking: the text of §4.3 sends the pseudo-identity PIDAV in clear, so any eavesdropper can link a vehicle's sessions. Fig. 3 masks it as TIDAV = h(X) ⊕ PIDAV; against that variant only the drones, not an outside eavesdropper, can link sessions.
  • P²AS-IoAV [3], past-session decryption: needs both parties' long-term private keys, or the trusted authority's copies of them, since the authority generates every private key. The drone's key alone only de-anonymises the vehicle.
  • P²AS-IoAV [3], forged message 1: the drone accepts a message 1 forged under a registered vehicle's identity (impersonation), but the forger does not learn that session's key.
  • PSRS-D2D [1], master-key extraction: two captured drones' certificates give the authority's secrets, which then also let the attacker impersonate drones that were never captured.

The flaws are in the protocol design, not just the curve: session keys built from public values, no forward secrecy, a static identifier sent in clear, a stored password verifier, and certificates whose algebra leaks the master key after two vehicles are captured. Even with a post-quantum KEM (P²AS-IoAV [3]), the design still fails.

Part 3 · Our protocol

PQ-V2V-AKE: a handshake designed against every one of those attacks

Each design rule answers one of the attacks above. The session key comes only from a fresh ML-KEM-768 secret and the full transcript. Each vehicle holds its own ML-DSA key; the authority only signs short-lived pseudonym certificates and keeps a revocation list. The responder checks the initiator before doing any key work.

An optional hybrid mode adds X25519, as TLS does today. Safety messages are signed separately with Falcon-512 and carry only a certificate digest between full certificates.

Compute is not the problem: a few milliseconds. The cost is size. Post-quantum keys, signatures and certificates make a handshake about 15 KB, against under 1 KB for the classical version of the same protocol.

Does a signed safety message still fit in one radio frame?

Real signatures over a 200-byte payload. The full certificate goes out once a second; the other nine messages carry an 8-byte digest of it.

ML-DSA-44 overflows a 1,400-byte frame even with the digest. Falcon-512 with the digest fits, so Falcon is the signature for broadcasts.

Part 4 · Network simulation

On a crowded road, the radio channel is the bottleneck

A discrete-event simulation: a 2 km highway with three lanes each way, 802.11p radio with real airtime, carrier sensing, collisions (including hidden terminals), retries and fragmentation, and a crypto processor in each vehicle. Crypto costs are measured from the real implementations, and a mode that runs the real protocol inside the simulation agrees with them.

60 vehicles, 6 seconds of steady-state traffic (recorded after a 6-second warm-up) replayed in your browser. Both runs use identical traffic and Falcon-512 safety messages; only the handshake differs. With ML-DSA certificates each handshake puts about 15 KB on a shared channel, so handshakes take longer and more of them fail.

Handshakes as the road fills up

Steady state (12-second runs, first 6 s discarded), mean of 5 seeds per point. "Same direction only" means sessions only with vehicles travelling the same way, as platooning would need.

The median handshake stays under the 100 ms budget up to about 100 vehicles for classical crypto and about 50 for both post-quantum variants (ML-DSA is right at the limit there, 95 ± 33 ms). Restricting sessions to the same direction roughly doubles that.

The bigger bottleneck: signatures on every safety message

Safety messages only, no handshakes. "Delivered" means received and verified within 300 m. Steady state, 5 seeds per point.

Ten signed messages a second per vehicle fill the channel. Falcon-512 saturates it from about 100 vehicles and ML-DSA-44 from about 50, while ECDSA still copes at 200. Quantum-safe broadcasting needs more than a signature swap: signing fewer messages, smaller certificates, or congestion control.

Conclusions

What this means for vehicles

  • Post-quantum cryptography is deployable now. It is software on the existing on-board unit, its compute cost is a few milliseconds, and our protocol keeps every security property the published designs lacked.
  • QKD behaves exactly as theory predicts, and that is its problem for vehicles. It detects any eavesdropper, but needs line-of-sight optics, loses rate exponentially with distance, and still needs PQC to authenticate its classical channel.
  • The three published schemes [1–3] fail at the design level. All seven attacks on them succeeded, including two on P²AS-IoAV [3], which already uses a post-quantum KEM. Quantum resistance does not help if the protocol design is broken.
  • The real cost of quantum safety is bandwidth. Bigger keys and signatures, not computation, limit how many vehicles a channel can serve. The broadcast layer needs redesigning, not just new algorithms.

Reproduce it

Every number on this page comes from running the code

git clone https://github.com/trilokdhakad/quantum-safe-v2v && cd quantum-safe-v2v
pip install -e ".[dev,oqs]"
python -m qsv2v.attacks          # the eight attacks, recovered secret vs victim's
python -m qsv2v.attacks --pq     # the same attacks against PQ-V2V-AKE
python -m qsv2v.experiments      # all ten experiments and every report figure
pytest -q                        # the test suite

Limits. This is a simulation study: no real vehicles, radios or quantum hardware. Timings come from one laptop and vary by up to 2× between runs (CPU frequency scaling), so treat compute figures as an order of magnitude. Safety messages carry a 200-byte payload, and splitting messages over 1,400 bytes into fragments is hypothetical (real 802.11p cannot). Scyther results mean "no attack found within bounds", not a full proof.
